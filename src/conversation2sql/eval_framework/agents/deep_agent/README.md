# deep_agent

A BIRD-Interact evaluation baseline built on LangChain's [`deepagents`](https://docs.langchain.com/oss/python/deepagents/overview).

## What it does

`deep_agent` resolves an **ambiguous** user query against a Postgres database under
the bird-coin patience budget — same task as the `bird_full` baseline. The one
difference: instead of dedicated schema tools (`get_schema`, `get_table_names`, …),
the agent explores the database through a **virtual filesystem** under `/db`, reading
it with deepagents' `ls` / `read_file` / `grep` / `glob`. Everything else — the
patience budget, `execute_sql`, `ask_user`, `submit_sql` — is reused unchanged from
`bird_baseline`.

Selected via `ConfigPipeline.baseline = deep_agent`; entry point
`run_agent_deep_agent` in `agent_code.py`.

## How it works

**Filesystem seed** (`filesystem_seed.py`, `build_db_filesystem(task)`) — mounts only
the catalog folder of the task's own database,
`<TaskData.deep_catalog_root>/<selected_database>/` (generated by
`scripts/generate_catalog.py`), into agent state under the `files` key:

| Path | Source | Rendering |
|------|--------|-----------|
| `/db/tables/<table>.md` | `<catalog>/<db>/tables/*.md` on disk | read verbatim (DDL + columns w/ descriptions + FKs) |
| `/db/tables/_foreign_key_constraints.md` | disk | all PK/FK constraints in the db |
| `/db/knowledge_base/<node>.md` | `masked_agent_kb` | one file per surviving node, re-rendered via `linearize_prerequisites` (node name used as-is, unsanitized) |

The KB is re-rendered per task from `masked_agent_kb` (not read from the catalog's
on-disk `knowledge_base/`), so per-sample masking is faithful: a masked prerequisite is
never collected and its dangling edge never renders. `deep_catalog_root` is set per run
(e.g. `data/bird_interact/catalog_bird_interact_lite`); a missing `<db>/tables/`
directory raises `FileNotFoundError`.

**Tools (4)** — a read-only subset of the deepagents FS (`ls`/`read_file`/`grep`/`glob`)
plus the reused `execute_sql`, `ask_user`, and `submit_sql`. The FS `execute` tool is
always dropped (it errors on the non-sandbox `StateBackend`); `write_file`/`edit_file`
appear only under the `deep_enable_fs_write` ablation.

**Build** — `create_agent` (not `create_deep_agent`) with `FilesystemMiddleware`
composed explicitly. `create_deep_agent` strips its built-in tools via a
*globally-registered* profile keyed by model provider, which would let concurrent runs
with different ablation flags clobber each other; composing middleware ourselves keeps
every toggle local to one agent build. The system prompt is handed to `create_agent`'s
`system_prompt=` (not the state `messages`) so the FS middleware appends to it as the
single leading system turn — otherwise vLLM rejects a second mid-history SystemMessage.

**Patience budget** — the same middleware appended last in the same relative order as
`bird_baseline` (`check_budget_limit` → `sanitize_thinking_history` →
`wrap_model_append_tool_message` → `tool_wrapper_patience_and_submit`), imported from
`bird_baseline/agent_callback.py`. Read costs are cheap (`0.5` coins each, static DB
info); reused tools pull their costs from the shared `TOOL_COSTS` table.

## Ablations

All default to `False` → minimal agent. Each flag is threaded
`ConfigReader` → `TaskData` (like `enable_psql_console`), gated in
`_build_deep_middleware`, paired with a prompt block and a run-dir slug suffix.

| Flag | Adds | Tools | Slug |
|------|------|-------|------|
| `deep_enable_todos` | `TodoListMiddleware` | `write_todos` | `__todos` |
| `deep_enable_subagents` | `SubAgentMiddleware` | `task` | `__subagents` |
| `deep_enable_summarization` | `SummarizationMiddleware` (reuses `model_agent`) | — | `__summar` |
| `deep_enable_fs_write` | FS write tools | `write_file`, `edit_file` | `__fswrite` |

`SubAgentMiddleware` needs ≥1 subagent; `_general_subagent` is a minimal
general-purpose one (tuning subagents is out of scope, so they're off by default).

Drive a flag via:

```bash
just eval --baseline deep_agent --extra "--deep_enable_todos true"
```

## Files

- `agent_code.py` — `run_agent_deep_agent` entry point + helpers `_build_fs_middleware`, `_build_deep_tools`, `_build_deep_middleware`.
- `filesystem_seed.py` — `build_db_filesystem` and the `deep_tool_costs` / `FS_TOOL_COSTS` cost tables.
- `agent_code_state.py` — `DeepAgentCustomState` merges deepagents' `FilesystemState` (`files`) with `bird_baseline`'s patience fields.
- `prompts.py` — `build_deep_agent_messages`; advertises `/db` (never schema tools), with conditional blocks per flag.
