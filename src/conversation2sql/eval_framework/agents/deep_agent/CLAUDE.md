# deep_agent

A BIRD-Interact evaluation baseline. It parallels `bird_full` (ambiguous query +
`ask_user`, under the bird-coin patience budget) but **replaces the `get_schema`-style
DB tools with a single read-only `bash` tool**: the agent explores the database by
reading per-task catalog files on disk via shell commands (`cat`, `ls`, `find`, `grep`,
etc.), and runs read-only SQL through `psql` — the same tool, no separate `execute_sql`.

## Why `create_agent` + middleware, not `create_deep_agent`

We build the agent with `create_agent` (the same primitive as `bird_baseline`) and
compose deepagents' `SubAgentMiddleware` ourselves when `deep_enable_subagents` is set.
This keeps every toggle local to one agent build rather than relying on a globally-
registered `HarnessProfile` keyed by model provider — global state is unworkable for
per-run ablations (two concurrent runs with different flags would clobber each other).

## Key files

- `agent_code.py` — `run_agent_deep_agent` (entry point) plus the unit-testable
  helpers `_build_deep_tools`, `_build_deep_middleware`.
- `catalog_seed.py` — `materialize_catalog_dir(task)` writes a fresh temp dir with
  `database_overview.md`, `tables/*.md`, and `knowledge_base/<node>.md` (re-rendered
  from `masked_agent_kb`); `deep_tool_costs()` is the cost table fed to
  `utils_process_agent_response`.
- `bash_tool.py` — `return_tool_bash(catalog_dir, pg_env)` builds the per-task `bash`
  tool. `build_pg_env` builds the `PG*` env vars + read-only `PGOPTIONS` from the task
  DSN. Commands are checked against the `ALLOWED_COMMANDS` whitelist
  (`{cat, ls, find, grep, head, tail, wc, psql}`) and a shell-metachar denylist
  (`; & > < \` $( ${ \n`). `psql` commands are additionally screened by the reused
  `_violates_psql_guardrail` from `bird_baseline`. A `# TODO(unmasked-kb-leak)` comment
  marks the deferred risk of `SELECT pg_read_file('…')`.
- `agent_code_state.py` — `DeepAgentCustomState` carries only the three patience
  fields (from `CustomAgentState`). No `files` state (the catalog is on disk, not in
  agent state) and no `captured_system_prompt`: the system prompt now rides as the
  leading message in the initial state (like `bird_baseline`), so it lands in the
  message history directly with no capture/re-insert.
- `prompts.py` — `build_deep_agent_messages`; the system prompt describes the on-disk
  catalog layout and `psql` usage, with a conditional block for `enable_subagents`.

## Catalog (`<tmp>/`, the bash tool's cwd)

`materialize_catalog_dir(task)` creates a fresh `tempfile.mkdtemp(prefix="deep_catalog_")`
per task run, populated from `<TaskData.deep_catalog_root>/<selected_database>/`
(generated by `scripts/generate_catalog.py`) and from `masked_agent_kb`:

| Path | Source | Notes |
|------|--------|-------|
| `<tmp>/database_overview.md` | `<catalog>/<db>/database_overview.md` on disk | copied if present; silently skipped if absent |
| `<tmp>/tables/<table>.md` | `<catalog>/<db>/tables/*.md` on disk | read verbatim (DDL + columns w/ descriptions + FKs) |
| `<tmp>/tables/_foreign_key_constraints.md` | disk | all PK/FK constraints in the db |
| `<tmp>/knowledge_base/<node>.md` | `TaskData.masked_agent_kb` | one file per surviving node, re-rendered via `linearize_prerequisites`; masked prerequisites never appear (no leak) |

The on-disk catalog path is never advertised to the model. A missing
`<deep_catalog_root>/<db>/tables/` directory raises `FileNotFoundError`. `deep_catalog_root`
is set per run (e.g. `data/bird_interact/catalog_bird_interact_lite`). The temp dir is
cleaned up in a `finally` block in `run_agent_deep_agent`.

## Tools (3)

- `bash` — read-only shell + psql, cwd = per-task catalog dir
- `submit_sql` — terminal graded action (reused from `bird_baseline`)
- `ask_user` — one clarifying question per call (reused from `bird_baseline`)

## Patience budget (reused unchanged)

The same middleware stack as `bird_baseline`, appended last in the same relative order:
`check_budget_limit` → `sanitize_thinking_history` →
`wrap_model_append_tool_message` → `tool_wrapper_patience_and_submit`. Do not
reimplement it — it is imported from `bird_baseline/agent_callback.py`.

## Ablation flags (all default `False` = minimal agent)

Threaded `ConfigReader` → `TaskData` exactly like `enable_psql_console`. The flag is
additive deepagents middleware, gated in `_build_deep_middleware`, with a matching prompt
block and a run-dir slug suffix (in `bash_scripts/utils/utils_evaluate.sh`, detected
from `--extra`).

| Flag | Adds | Slug |
|------|------|------|
| `deep_enable_subagents` | `SubAgentMiddleware` (`task`) | `__subagents` |

`SubAgentMiddleware` requires ≥1 subagent (each needing a `model` and `tools`);
`_general_subagent` is a minimal general-purpose one — tuning subagents is out of
scope (off by default). Drive the flag via
`just eval --baseline deep_agent --extra "--deep_enable_subagents true"`.
